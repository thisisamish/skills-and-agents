# Career Master Document Format

This file defines the canonical structure for `CMD.md`. The document is a comprehensive career evidence record, not a resume. Every substantive claim must be supported by information recorded in `NOTES.md`.

## 4. Current Role — Detailed Context

Describe the current role at an appropriate, sanitized level: product/domain, responsibilities, technical environment, development process, team/ownership model, relevant constraints, and scope. Do not include confidential company information.

Group accomplishments by engineering capability rather than chronology. ## 8. Quantified Metrics

Only include verified metrics.

| Metric | Value | Period | Meaning | Evidence |
|---|---:|---|---|---|

Possible types include features/stories, defects, releases, customers/issues, modules/components, meaningful code scale, performance changes, test coverage, documentation, users/developers reached, automation savings, adoption, awards, and ratings.

## 9. Technical Skills

Separate into:

### Frameworks/Libraries
### Operating Systems
### Build Systems
### Version Control
### CI/CD
### Cloud/Infrastructure
### Messaging
### Debugging/Profiling

### Other

For each skill, optionally include depth, production usage, approximate duration, and representative evidence. Do not claim proficiency merely because a technology was encountered.

## 10. Engineering Capabilities

Track transferable capabilities independent of technology, such as system design, reverse engineering, large-codebase navigation, production debugging, performance analysis, memory management, concurrency, distributed systems, database reasoning, refactoring, testing, automation, documentation, technical communication, mentoring, ownership, and technical decision-making. Support important capabilities with evidence.

## 11. Knowledge & Documentation Contributions

Track document count, topics, audience, adoption/use, resulting improvements, and evidence. Do not store proprietary document contents.

## 12. Recognition

Track performance ratings, awards, manager/peer recognition, increased responsibility, trusted ownership, requests for technical assistance, and other objective signals of trust.

## 15. Career Goals

Separate into:

### Short-term
### Medium-term
### Long-term

Include target roles, technical domains, companies/markets where relevant, compensation, leadership, and learning goals. Clearly label aspirations as goals, not evidence.

## 16. Evidence Gaps

List valuable missing information (for example, release number, before/after performance, adoption, or affected module count). Do not fabricate values to fill gaps.

## 17. Resume Extraction Notes

Maintain brief guidance for future tailoring:

- Strongest general bullets
- Strongest technical bullets
- Strongest leadership bullets
- Strongest measurable accomplishments
- Bullets to avoid or rewrite
- Technology keywords supported by evidence

## 18. Career Narrative

Periodically synthesize:

1. What kinds of problems does this engineer repeatedly solve?
2. How has scope increased?
3. What capabilities are becoming distinctive?
4. What evidence demonstrates increasing responsibility?
5. What capabilities should be developed next?

This is a synthesis, not a self-congratulatory summary.

## Format rules

1. Preserve this section structure.
2. Do not invent sections unless clearly necessary; update this format first if a new section is required.
3. Keep historical facts traceable to `NOTES.md`.
4. Prefer evidence over adjectives.
5. Distinguish facts, goals, interpretations, and recommendations.
6. Never store confidential company information.
7. Never fabricate metrics.
8. Keep resume bullets separate from the comprehensive evidence.
9. Update `Last updated` whenever CMD changes.
10. The CMD may grow indefinitely; it is not constrained to one or two pages.
